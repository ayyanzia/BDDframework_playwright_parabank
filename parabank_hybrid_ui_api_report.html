What is Cross-Validation?

In this context, Cross-Validation means that our testing system performs an action in the web browser (the frontend interface that a user sees) and then independently checks the server database via a direct API call (the backend) to confirm both sides agree.

This ensures that what the user sees on their screen perfectly matches the true data stored deep within the banking system, preventing display errors or hidden server failures.

MODULE 1: User Registration (2 tests)
Test: UI Registration form creates valid backend record verified by REST API
Description: Verifies that when a person registers through the website's registration form, their account is genuinely created in the server's database and they can be found via the backend API.
Steps:
  1. Generate a random new user with unique name and credentials.
  2. Navigate to the registration page in the browser.
  3. Fill in all registration fields (first name, last name, username, password, etc.).
  4. Click the Register button.
  5. Verify the browser shows a success message (welcome, created, or account text).
  6. Independently query the server's login API using the new credentials.
  7. Compare the username, first name, and last name from the browser registration with the data returned by the server API.
Expected Result: The browser shows registration success AND the server API returns matching user data (same username, first name, last name).
Actual Result: PASSED
What Was Cross-Validated: UI username equals API username, UI firstName equals API firstName, UI lastName equals API lastName.
Test: UI Registration with missing fields fails gracefully on UI and returns 400/500 on backend
Description: Ensures that submitting an incomplete registration form is rejected by both the website and the server independently.
Steps:
  1. Create a user profile with the first name intentionally left blank.
  2. Navigate to the registration page.
  3. Fill in only the username and password (leaving first name empty).
  4. Click Register.
  5. Verify the browser displays an error message mentioning 'is required' or 'error'.
  6. Independently submit the same incomplete data directly to the server.
  7. Verify the server also rejects it.
Expected Result: Browser shows a validation error AND server returns an error status.
Actual Result: PASSED
What Was Cross-Validated: Form rejection mechanism consistency across frontend and backend.
